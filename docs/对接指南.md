# 对外接口与 MCP 对接指南

这个文档写给"要让别的程序或 Agent 调用 XY"的人。

XY 有三种被调用的形态，能力边界不同，先看这张表再往下读：

| 形态 | 调用方 | 需要什么 | 适合什么 |
|---|---|---|---|
| **HTTP（/api/v1）** | 任何能发 HTTP 的程序、脚本、Agent | HTTP 客户端 + Token | 当成一个会办事的子服务 |
| **SSE 流** | 同上，但要看到执行过程 | HTTP 客户端（会读流） | 长任务、要做进度展示 |
| **MCP（stdio）** | Claude Desktop、Cursor、任何 MCP 主机 | 只改一个 json 配置 | 把 XY 当工具包挂进现有 Agent |

---

## 一、HTTP 接口

### 1.1 启动

```bash
# 桌面版
desktop.bat

# 或网页版（控制台会打印接口地址和 Token）
.venv\Scripts\python.exe web.py
```

启动后控制台会打印：

```
[对外接口] 已就绪：http://127.0.0.1:7860/api/v1
           接口文档：http://127.0.0.1:7860/api/v1/docs
           Token   ：<32 位随机串>
```

浏览器打开 `/api/v1/docs` 是 Swagger UI，可以直接在页面上点「Authorize」填 Token 试接口。

### 1.2 鉴权

除了 `/health`，所有端点都要一个 Bearer Token：

```
Authorization: Bearer <token>
```

Token 来源优先级：

1. 环境变量 `API_TOKEN`（不想要随机值就自己指定）
2. 数据目录里已保存的 `api_token.txt`
3. 都没有时自动生成并写入 `~/.xy/api_token.txt`

不想要鉴权（**仅限本机**）：`set API_AUTH=off`。

### 1.3 端点清单

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/health` | 探活，免鉴权，返回模型/知识库/会话状态 |
| GET | `/api/v1/tools` | 当前对外暴露的工具清单（JSON Schema） |
| POST | `/api/v1/chat` | 一次问答，等结果 |
| POST | `/api/v1/chat/stream` | 一次问答，SSE 推执行步骤 |
| GET | `/api/v1/kb/stats` | 知识库统计 |
| POST | `/api/v1/kb/search` | 语义检索 |
| GET | `/api/v1/sessions` | 会话池状态 |
| DELETE | `/api/v1/sessions/{id}` | 结束一个会话 |
| GET | `/api/v1/docs` | Swagger UI（免鉴权） |
| GET | `/api/v1/openapi.json` | OpenAPI schema（免鉴权） |

### 1.4 一次问答

```bash
TOKEN=$(cat ~/.xy/api_token.txt)

curl -s -X POST http://127.0.0.1:7860/api/v1/chat \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"message":"知识库里关于 RAG 的内容有哪些","session_id":"demo-1"}'
```

返回：

```json
{
  "reply": "知识库里关于 RAG 的内容主要是……",
  "session_id": "demo-1",
  "elapsed_ms": 8421
}
```

**`session_id` 决定上下文边界**：同一个 id 连续提问会带上文，不同 id 互不可见。不传就是 `default`。

### 1.5 流式（长任务用这个）

Agent 跑一轮可能 30~60 秒（5~8 次工具调用）。普通 HTTP 客户端默认 30 秒超时，等不到结果就断开。用 SSE 版本，服务端每 15 秒发一次心跳，连接不会被中间设备掐掉。

```bash
curl -N -X POST http://127.0.0.1:7860/api/v1/chat/stream \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"message":"帮我分析一下知识库里那份合同的风险点","session_id":"demo-2"}'
```

事件序列：

```
event: start
data: {"session_id":"demo-2"}

event: step
data: {"text":"search_knowledge → 命中 4 段"}

event: step
data: {"text":"read_local_file → /path/to/x.pdf"}

event: done
data: {"reply":"...","session_id":"demo-2","elapsed_ms":31240}
```

- `step` 是工具调用事件（工具名 → 结果预览），不是逐字流式
- 15 秒没有事件时会有 `: keep-alive` 注释行（SSE 规范里客户端会忽略，但连接保持活着）
- 出错时发 `event: error`，之后连接关闭

### 1.6 Python 客户端

```python
import httpx

TOKEN = open(r"C:\Users\you\.xy\api_token.txt", encoding="utf-8").read().strip()
client = httpx.Client(
    base_url="http://127.0.0.1:7860",
    headers={"Authorization": f"Bearer {TOKEN}"},
    timeout=180,          # 一轮可能跑一分钟，别用默认 30 秒
    trust_env=False,      # 避免走到系统代理
)

r = client.post("/api/v1/chat", json={"message": "你好", "session_id": "py-demo"})
print(r.json()["reply"])
```

## 二、MCP（推荐给 Agent 用）

MCP 是 Agent 之间协作的通用协议。配好之后，Claude Desktop / Cursor 会把 XY 的工具当成自己的工具来用。

### 2.1 两种用法

**`ask_xy`（复合工具）** —— 整个 Agent 就是一把工具：

> 你："XY，帮我看下知识库里那份采购合同的付款条款风险"
> Claude 调 `ask_xy(question="...")` → XY 自己检索、读文档、跑 ReAct、回一段结论

适合开放式问题。对端不需要知道 XY 内部有 13 个工具。

**原子工具（默认 10 个）** —— 对端当大脑：

| 工具 | 作用 |
|---|---|
| `now` | 当前时间 |
| `list_files` / `read_file` | 读写工作区（读） |
| `search_web` | 联网搜索 |
| `calculator` | 安全计算 |
| `search_knowledge` | 知识库语义检索 |
| `knowledge_stats` | 知识库统计 |
| `list_local_files` / `read_local_file` | 读本机文件（白名单） |
| `analyze_document` | 分析文档要点 |

适合宿主已经有编排逻辑、只想借你的读取和检索能力。

### 2.2 Claude Desktop 配置

编辑 `%APPDATA%\Claude\claude_desktop_config.json`：

```json
{
  "mcpServers": {
    "xy-agent": {
      "command": "C:\\Users\\you\\WorkBuddy\\2026-10-27-18-26-17\\.venv\\Scripts\\python.exe",
      "args": ["C:\\Users\\you\\WorkBuddy\\2026-10-27-18-26-17\\mcp_server.py"]
    }
  }
}
```

改完**完全退出** Claude Desktop 再打开（托盘图标也要退），否则不重新加载。

### 2.3 Cursor 配置

项目里建 `.cursor/mcp.json`，内容同上（或写到用户级 `~/.cursor/mcp.json`）。

### 2.4 验证

不用等宿主，直接看工具能不能列出来：

```bash
.venv\Scripts\python.exe -c "
import asyncio, sys, os
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

async def main():
    p = StdioServerParameters(command=sys.executable, args=['mcp_server.py'], env=dict(os.environ))
    async with stdio_client(p) as (r, w):
        async with ClientSession(r, w) as s:
            await s.initialize()
            print([t.name for t in (await s.list_tools()).tools])

asyncio.run(main())
"
```

应输出 11 个工具（含 `ask_xy`）。

### 2.5 关于 stdio

MCP 用 stdio 传输，不是 HTTP：

- 不用端口、不用 Token、不会被防火墙拦
- 由宿主进程拉起，宿主退出它就退出
- 第一次调用要加载模型和向量库，约 3~6 秒，之后是热的

要跨机器提供，得换 `streamable-http` 传输，那是另一套事（还要配鉴权）。

## 三、安全边界

这是重点，别跳。

### 3.1 默认只读

对外接口默认**不暴露**三个危险工具：

| 工具 | 为什么默认关 |
|---|---|
| `run_command` | 实现是 `shell=True` + 5 个词的黑名单，实质上接近任意命令执行 |
| `write_file` | 能写桌面 / 文档 / 下载目录 |
| `ingest_local_file` | 能往知识库里塞内容，会污染后续所有检索 |

要开（**确认你知道后果**）：

```bash
set XY_EXTERNAL_ALLOW=write,shell,ingest
```

可以只开一部分，比如只允许写：`set XY_EXTERNAL_ALLOW=write`。

### 3.2 两层闸门

即使宿主绕过工具列表直接请求一个未暴露的工具，也会被拒：

1. **工具列表层**：`external_tool_names()` 决定模型能看见哪些工具
2. **执行层**：`confirm.py` 在无人值守来源（api / mcp）下只放行白名单内的工具

第二层是关键 —— 模型自己"想起"一个工具也没用，`execute_tool()` 会拦住。

来源是通过 `contextvars` 标记的，不是全局改确认模式。这样网页用户正在弹确认框时，外部请求不会去等一个永远不会有人点的确认（那会白挂 120 秒）。

### 3.3 并发与会话

| 问题 | 处理 |
|---|---|
| 两个 Agent 串会话 | 按 `session_id` 分配 Agent 实例，只隔离 `messages` |
| 同一会话并发 | 该会话加锁串行，一轮没跑完不接受下一轮 |
| 会话越积越多 | 默认最多 16 个、空闲 30 分钟回收（`MAX_SESSIONS` / `SESSION_TTL`）|

知识库和长期记忆是**跨会话共享**的 —— 那是产品能力，不是 bug。

### 3.4 网络暴露

默认只绑 `127.0.0.1`。要让局域网内别的机器调，得改 `WEB_HOST=0.0.0.0`，此时**必须**保留 Token（`API_AUTH` 别关）。

## 四、常见问题

**Q：调用返回 503 "Agent 尚未就绪"**
服务还在初始化（加载模型和向量库），等几秒重试。`/api/v1/health` 里的 `status` 变成 `ok` 就好了。

**Q：调用超时，但我这边日志显示还在跑**
用了 `/chat` 而不是 `/chat/stream`。Agent 一轮可能一分钟，普通客户端默认 30 秒就断。两个办法：客户端把 timeout 调到 180 秒，或者换流式版本。

**Q：Message 里提到"知识库那份文档"，它说要路径**
这是模型行为。用 `ask_xy` 和 `/chat` 时它是完整 Agent，会自己检索；但如果只调原子工具 `read_local_file`，那确实需要路径。

**Q：MCP 连上了但工具列表是空的**
看宿主日志。常见原因是 `command` 路径写错，或者用了系统 Python 而不是 `.venv` 里的（依赖不在）。

**Q：改了 `XY_EXTERNAL_ALLOW` 但没生效**
MCP 服务是宿主拉起的子进程，改完环境变量要重启宿主（Claude Desktop 完全退出再开）。

**Q：网页和外部接口同时用，会不会互相干扰**
不会。网页固定用 `web` 会话，外部用各自的 `session_id`。模型和知识库是共享的，换模型对两边同时生效。

# 4. MCP 工具列得出来
#    见 2.4
